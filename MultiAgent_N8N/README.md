# Multi AI Agent – Telegram Research Assistant (n8n)

A Telegram bot built in n8n using a **multi-agent (orchestrator + specialists)** pattern. A Parent AI Agent reads each Telegram message, decides which specialist should handle it, and replies with one combined answer.

- **Amazon Research Agent** finds, compares and recommends physical products from **Amazon India** (via SerpApi).
- **Web Research Agent** handles current or external information such as news, companies, technologies and documentation (via SerpApi Google Search).

Example messages:

```
Best refrigerator under ₹50,000, choose the best 3
What are the latest developments in humanoid robots?
Find the best 3 Wi-Fi routers under ₹10,000 and explain which Wi-Fi technology is newest
```

---

## Architecture

```
Telegram Trigger ──► Parent AI Agent (orchestrator) ──► Send a text message (Telegram)
                        │
                        ├── OpenAI Chat Model   (primary LLM, gpt-4.1-mini)
                        ├── OpenAI Chat Model2  (fallback LLM, gpt-4.1-mini)
                        ├── Simple Memory       (session = Telegram chat ID)
                        │
                        ├── Amazon Research Agent (agent tool)
                        │      ├── OpenAI Chat Model1
                        │      └── Amazon search in SerpApi  (amazon.in)
                        │
                        └── Web Research Agent (agent tool)
                               ├── OpenAI Chat Model3
                               └── Google search in SerpApi
```

## Nodes

| Node | Type | Purpose |
|---|---|---|
| Telegram Trigger | Telegram Trigger (`message` updates) | Receives user messages from the bot |
| Parent AI Agent | AI Agent (v3.1, fallback enabled) | Orchestrator: routes to specialists and writes the final answer |
| OpenAI Chat Model | OpenAI `gpt-4.1-mini` | Primary model for the Parent agent |
| OpenAI Chat Model2 | OpenAI `gpt-4.1-mini` | **Fallback** model for the Parent agent |
| Simple Memory | Window Buffer Memory | Per-user conversation memory, keyed by `message.chat.id` |
| Amazon Research Agent | AI Agent Tool | Product search, shortlist (up to 3), comparison, best pick |
| OpenAI Chat Model1 | OpenAI `gpt-4.1-mini` | Model for the Amazon agent |
| Amazon search in SerpApi | SerpApi Tool – Amazon | Searches `amazon.in`; the query is generated by the agent (`$fromAI`) |
| Web Research Agent | AI Agent Tool | Current or external web research with sources |
| OpenAI Chat Model3 | OpenAI `gpt-4.1-mini` | Model for the Web agent |
| Google search in SerpApi | SerpApi Tool – Google | Web search; the query is generated by the agent (`$fromAI`) |
| Send a text message | Telegram – send | Replies to the same chat with `$json.output` |

## Routing logic (Parent agent system message)

| User intent | Routed to |
|---|---|
| Find, buy, recommend, compare or shortlist a **physical product** (Amazon doesn't need to be mentioned) | Amazon Research Agent |
| Current, recent or external info: news, companies, technologies, statistics, documentation | Web Research Agent |
| A request that needs both (e.g. products + latest tech explanation) | Both, results combined |
| Greetings, simple explanations, brainstorming | Answered directly, no tools |

Key rules built into the prompts:
- **Preserve requirements**: budget, currency, quantity, brand, features and intended use are passed unchanged to the specialist.
- **No unnecessary clarification**: ask only when the product category or topic is genuinely unknown.
- **Anti-hallucination**: never invent prices, ratings, specs, links, URLs, sources or current events. Missing data is reported as unavailable.
- **Hidden routing**: the final reply never mentions agents, tools or internal reasoning.

## Setup

See [REQUIREMENTS.md](REQUIREMENTS.md) for prerequisites.

1. **Create a Telegram bot** with [@BotFather](https://t.me/BotFather) (`/newbot`) and copy the bot token.
2. **Import** `Multi AI Agent.json` into n8n (*Workflows → Import from File*).
3. **Credentials** – attach or recreate:
   - `Telegram account` on *Telegram Trigger* and *Send a text message*
   - `OpenAI account` on all four OpenAI Chat Model nodes
   - `SerpApi account` on both SerpApi tool nodes
4. **Publish** the workflow. n8n then registers the Telegram webhook automatically. This needs a public HTTPS URL.

## Usage

Open your bot in Telegram and send a message. Each Telegram chat has its own memory, so follow-up questions such as *"which of those is most energy efficient?"* work within the same chat.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Bot doesn't respond | Workflow not published, or the webhook can't reach n8n | Publish; check `WEBHOOK_URL` is your public HTTPS domain |
| "Conflict: can't use getUpdates while webhook is active" or webhook errors | Another workflow or service uses the same bot token | Use one Telegram Trigger per bot token |
| Product answer without real prices or links | Parent answered from its own knowledge | Check the execution: the Amazon Research Agent should have been called; strengthen routing in the system message |
| SerpApi errors / empty results | API key invalid or monthly search quota used up | Check usage on the SerpApi dashboard |
| Telegram send fails on long answers | Telegram message limit (4096 characters) | Ask the agent to keep replies concise, or split long output before sending |
| Parse errors with special characters | Telegram formatting mode | Keep the default (no parse mode), or escape Markdown characters |
| Primary model errors | OpenAI rate limit or outage | The fallback model (OpenAI Chat Model2) takes over automatically. For real resilience, use a different provider or model for the fallback. |

## Notes and possible improvements

- The primary and fallback models are both OpenAI `gpt-4.1-mini` on the same credential. A fallback on a different provider (e.g. Anthropic or Gemini) protects against provider outages, not just transient errors.
- Each research request costs one or more SerpApi searches. Monitor your quota.
- The bot is open to anyone who finds it. To restrict it, add an **IF** node after the trigger that allows only your own Telegram chat ID(s).
